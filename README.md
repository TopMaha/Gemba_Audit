# Gemba Walk App

เว็บแอปสำหรับผู้จัดการโรงงาน ใช้วางแผน บันทึก และติดตามผลการเดินตรวจหน้างาน (Gemba Walk)
ออกแบบให้ใช้บนมือถือเป็นหลัก รองรับสองภาษา ไทย/อังกฤษ สร้างตาม `MVP-Spec-TH.md`

---

## 1. เปิดใช้งาน

**วิธีที่ 1 — โหมดพัฒนา (แนะนำตอนแก้โค้ด)**

```bash
npm install
npm run dev
```

เปิด <http://localhost:8080> · ถ้าเจอจอขาว ให้กด `Ctrl` + `Shift` + `R` เพื่อล้างแคชของเบราว์เซอร์ก่อน

**วิธีที่ 2 — ดับเบิลคลิกเปิดไฟล์ (ไม่ต้องรันเซิร์ฟเวอร์)**

```bash
npm run build:file
```

แล้วดับเบิลคลิก `dist/index.html` ได้เลย (build โหมดนี้ใช้ path แบบ relative และสลับไปใช้
HashRouter อัตโนมัติเมื่อเปิดแบบ `file://` จึงเปิดตรง ๆ ได้ทั้งแอป)

> ⚠️ อย่าใช้ `npm run build` ธรรมดาแล้วดับเบิลคลิก — โหมดนั้นใช้ path แบบ absolute (`/assets/…`)
> สำหรับ deploy ขึ้นโฮสต์ เปิดด้วย `file://` จะได้จอขาว

**วิธีที่ 3 — ทดสอบไฟล์ที่ build แล้วบนเซิร์ฟเวอร์**

```bash
npm run preview
```

| คำสั่ง | หน้าที่ |
|---|---|
| `npm run dev` | รันโหมดพัฒนา (พอร์ต 8080) |
| `npm run build` | สร้างไฟล์สำหรับ deploy ขึ้นโฮสต์ (Cloudflare Pages) ในโฟลเดอร์ `dist/` |
| `npm run build:file` | สร้างไฟล์แบบ relative path สำหรับดับเบิลคลิกเปิดด้วย `file://` |
| `npm run preview` | ดูตัวอย่างไฟล์ที่ build แล้ว |
| `npm run lint` | ตรวจชนิดข้อมูลด้วย TypeScript (`tsc --noEmit`) |
| `npm run test` | รันชุดทดสอบ (Vitest) |

**รหัสสำหรับทดลองใช้**

- ผู้จัดการ: `1001` – `1011` (รหัส `1012` ถูกตั้งเป็น Inactive ไว้ทดสอบการถูกปิดบัญชี)
- ผู้ดูแลระบบ (`/admin`): `9999`

## 2. สถานะระบบหลังบ้าน

**ยังไม่ได้ต่อ backend จริง** — ตามที่ตกลงกันไว้ว่า "ระบบหลังบ้านเดี๋ยวว่ากัน"

เวอร์ชันนี้ใช้ชั้นข้อมูลในเครื่องแทน เพื่อให้แอปใช้งานได้จริงทันทีตั้งแต่เปิดครั้งแรก

| ส่วน | ที่เก็บจริงตอนนี้ | ของจริงในอนาคต |
|---|---|---|
| ตารางข้อมูลทั้งหมด | `localStorage` (คีย์ `gemba.db.v1`) | ฐานข้อมูล (Lovable Cloud / Supabase / REST) |
| ไฟล์รูปภาพ | `IndexedDB` (คีย์ `local:…`) | Storage bucket |

โครงตารางตรงตามสเปกทุกคอลัมน์ (`src/lib/types.ts`) และข้อมูลตัวอย่างถูกสร้างครั้งแรกอัตโนมัติ
(ผู้ใช้ 12 คน, พื้นที่ 26 แห่ง, หัวข้อ 8 หัวข้อ, แผน/บันทึกย้อนหลัง ~2 เดือน)

### จะต่อของจริงต้องแก้แค่ 2 ไฟล์

1. `src/lib/db.ts` — เปลี่ยน `query()` / `mutate()` ให้ยิง HTTP แทนการอ่าน localStorage
2. `src/lib/api.ts` — เปลี่ยนฟังก์ชันโดเมนแต่ละตัวให้เรียก endpoint จริง (ชื่อฟังก์ชัน/ชนิดข้อมูลคงเดิม)

หน้าจอทั้งหมดเรียกผ่าน hooks ใน `src/hooks/useData.ts` (TanStack Query) จึง **ไม่ต้องแก้หน้าจอเลย**

รูปภาพ: `src/lib/photos.ts` มีจุดเดียวที่ต้องเปลี่ยน (`savePhoto` → อัปโหลดขึ้น bucket, `photoUrl` → คืน URL จริง)
ค่าที่ไม่ขึ้นต้นด้วย `local:` จะถูกใช้เป็น URL ตรง ๆ อยู่แล้ว จึงย้ายทีละส่วนได้

## 6. สูตรคำนวณ (มีชุดทดสอบครอบคลุมใน `src/lib/__tests__/calc.test.ts`)

```text
Adherence %  = แผนที่เดินแล้ว ÷ แผนที่ถึงกำหนดแล้วในช่วง × 100
               (ไม่นับแผนที่ยกเลิก และไม่นับแผนที่ยังไม่ถึงกำหนด)

Completion % = จำนวนผู้ต้องเดินที่เดินหัวข้อนั้น (ไม่ซ้ำคน) ÷ ผู้ต้องเดินทั้งหมด × 100
               ผู้ต้องเดิน = คนที่ผู้ดูแลกำหนดในหน้าตั้งค่า › ผู้เดิน Gemba
               (ยังไม่กำหนดใครเลย = ใช้ทุกคนที่มีสิทธิ์เข้าใช้งานแทน)
Overall %    = ผลรวม Actual ทุกหัวข้อที่เลือก ÷ ผลรวม Plan ทุกหัวข้อที่เลือก × 100
```

- ทุกเปอร์เซ็นต์ปัดลง (floor) ตามตัวอย่างในสเปก — 17/30 = 56%
- แถบสี: เขียว ≥ 80%, ส้ม 50–79%, แดง < 50%
- Rank: เรียงตามจำนวนครั้งที่เดิน หากเท่ากันใช้ Adherence แล้วตามด้วยจำนวนหัวข้อ

## 7. สองจุดที่ต่างจากสเปกเล็กน้อย (ตั้งใจ — ปรับกลับได้)

1. **หน้า "แผนการเดิน" มีกลุ่ม "เลยกำหนด" อยู่ด้านบน**
   สเปกระบุให้แสดงเฉพาะแผนตั้งแต่วันนี้เป็นต้นไป แต่ถ้าทำแบบนั้นตรง ๆ แผนที่ยังไม่ได้เดิน
   และเลยวันไปแล้วจะหายไปเงียบ ๆ จึงแยกเป็นกลุ่มติดป้ายสีแดงไว้ให้เห็นชัด
   (ลบออกได้ที่ตัวแปร `overdue` ใน `src/pages/Plan.tsx`)

2. **Adherence ไม่นับแผนที่ยังไม่ถึงกำหนด**
   ถ้านับแผนทั้งสัปดาห์/เดือนตรงตามตัวอักษร ตัวเลขกลางสัปดาห์จะต่ำผิดจริง
   (วันพุธก็โดนหักคะแนนจากแผนวันศุกร์) จำนวนที่ยังไม่ถึงกำหนดแสดงแยกไว้ในทูลทิป
   (ปรับกลับได้ที่ฟังก์ชัน `adherence()` ใน `src/lib/calc.ts` — ลบเงื่อนไข `asOf` ออก)

## 8. ข้อควรรู้

- **โซนเวลา** — ใช้ Asia/Bangkok ทั้งหมด สัปดาห์เริ่มวันอาทิตย์ ห้ามใช้ `new Date()` ตรง ๆ
  ในหน้าจอเพื่อคำนวณวันที่ ให้เรียกผ่าน `src/lib/time.ts` เสมอ
- **ภาษา** — ค่าเริ่มต้นภาษาไทย (แสดงปี พ.ศ.) สลับที่สวิตช์ TH/EN บนส่วนหัว ระบบจำค่าไว้
- **หัวข้อการเดิน** — เก็บใน `gemba_plans.theme_ids` (อาร์เรย์) โดยยังคง `theme_id` ค่าเดียวไว้
  เพื่อความเข้ากันได้กับโค้ดเดิม
- **การแก้ไขย้อนหลัง** — ทุกครั้งบันทึกลง `change_history` (ค่าเดิม/ค่าใหม่/ผู้แก้ไข/เวลา)
  แก้หัวข้อการเดินย้อนหลังได้เฉพาะรายการที่ผูกกับแผน และจะอัปเดตที่แผนให้ตรงกันด้วย
- **รูปภาพ** — ย่อด้านยาวไม่เกิน 1400px แล้วแปลงเป็น JPEG ก่อนเก็บ
  ร่างบันทึก (ข้อความ + รูป) ถูกเก็บในเครื่องระหว่างกรอก มือถือปิดแท็บตอนเปิดกล้องก็ไม่หาย
- **จุดรวมปัญหา** — บันทึกที่ "พบปัญหา" เด้งไปหาผู้รับเรื่องที่ตั้งไว้ใน ตั้งค่า › ระบบ (เริ่มต้น T-815)
- **ปิดบัญชีมีผลทันที** — Admin ปิด `is_active` แล้วผู้ใช้จะถูกเด้งออกจากระบบในรอบโหลดข้อมูลถัดไป
- **ล้างข้อมูล** — `/admin/settings` → แท็บ "ระบบ" มีทั้งส่งออก JSON, ล้างเฉพาะแผน/บันทึก,
  และล้างทั้งหมดเพื่อสร้างข้อมูลตัวอย่างใหม่
